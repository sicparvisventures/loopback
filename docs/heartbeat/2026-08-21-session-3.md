### The native app did not compile
The scaffolded Swift sources had never been built. Fixing this was the bulk
of the session — see the commit log for the full breakdown. Highlights:

- `Package.swift` pointed at `Sources/Loopback`, but sources live in
  `Loopback/` (Xcode layout), so the target resolved to **zero files**.
- 20 compile errors: a non-existent ScreenCaptureKit permission API,
  main-actor isolation violations in the audio capture callback, a pointer
  escaping `withUnsafeBytes`, `[String: Any]` where `Encodable` was required,
  Realtime V1 APIs against a V2 client, `override init()` on a non-subclass,
  and macOS 15-only SwiftUI (`.foregroundStyle(.accent)`) under a macOS 14
  deployment target.
- Then it compiled and **crashed on launch**: `SupabaseClient.init`
  preconditions on an absolute http(s) URL, and both `LoopbackApp` and
  `SupabaseService` built one from the literal `"YOUR_SUPABASE_URL"`.

## Blockers / Questions
- **Vercel env vars are not set.** The build is green without them, but every
  Supabase call fails at runtime. `NEXT_PUBLIC_SUPABASE_URL` and
  `NEXT_PUBLIC_SUPABASE_ANON_KEY` must be added in the Vercel dashboard.
  Deliberately not copied from `web/.env.local` unattended.
- **Builds are not notarised.** Browser downloads hit Gatekeeper on first
  launch. Fixing this properly needs an Apple Developer ID ($99/yr) plus
  `APPLE_ID`, `APPLE_TEAM_ID`, and an app-specific password in repo secrets.
  The `curl` installer sidesteps it because curl does not set the quarantine
  attribute.
- **Ad-hoc signatures change every build**, so macOS re-prompts for Screen
  Recording permission after each update. A real signing identity fixes this
  too.
- The Vercel project sits under the `reserve4you` team — the only team on the
  connected account. Say so if it belongs elsewhere.
